> 조사 서브에이전트가 **가장 먼저 읽는** 파일. `{ }` 는 첨부에서 자동 추출한 값, `[ ]` 는 첨부·요청에서 도출한 세부 분석 축으로 채운다.
> 이 파일을 채운 뒤 조사 단위(r1~rN)별로 서브에이전트를 병렬 실행한다.

- "Open-source" 표기 대비 라이선스 편차(AGPL·자체 라이선스·모델 가중치 비상업)

- 도식에 없는 주요 도구·상용 서비스·평가 관점(벤치마크·비용·한국어/CJK)
- 푸터·말풍선 주장의 근거 여부

6. `### 성능·벤치마크` — 공식 수치(출처·벤치마크명·버전), 속도(하드웨어 명시), 알려진 한계
7. `### 사용 및 활용용도` — 적합한 데이터·업무, 파이프라인에서의 역할, 부적합 사례

## 품질 규칙 (반드시)
- 1차 출처(논문 arXiv, 공식 문서, GitHub README/코드/릴리스, 벤더 공식 블로그·백서, 모델 카드, 표준 명세) 우선. 확인 못 한 사실은 `[미확인]`. 추측 금지. 수치는 출처 병기.
- 저장소는 `gh api repos/OWNER/REPO --jq '{full_name,stargazers_count,license:.license.spdx_id,language,pushed_at,created_at,archived}'` 로 **직접 조회**. 코드 구조는 `gh api repos/OWNER/REPO/contents/PATH` 또는 README. 최신 릴리스 `gh api repos/OWNER/REPO/releases/latest --jq '.tag_name+" "+.published_at'`.
- 패키지 버전: PyPI `curl -s https://pypi.org/pypi/PKG/json`, npm `npm view PKG version`, crates `curl -s https://crates.io/api/v1/crates/PKG`.
- arXiv 논문은 ID + 정확한 제목 + 연도. `curl -s https://arxiv.org/abs/ID | grep citation_title` 로 존재 확인 안 되면 쓰지 말 것.
- 표준·백서·블로그는 정식 제목·발행 주체·연도·URL.
- **`# ` 블록 하나 끝낼 때마다 파일에 저장(append)**. 몰아 쓰다 중단되면 소실.
- `{root}` 의 다른 보고서들(형식 참고용)은 **출처로 쓰지 말 것. 읽지도 말 것.**
- 도식의 부정확/과장/오탈자/누락은 근거와 함께 지적(도식 판정 표).
- 분량: 항목 블록당 90~170줄, 기타 블록 60~150줄. 표·코드·불릿 적극 사용, 구현 관점(실제 API·클래스명·설정·코드) 필수.
- 조사 단계에서 도구를 직접 설치·실행하지 말 것(웹·gh·curl 조사만) — 실측 실험은 별도 단계(`--experiment`).

## 파일 형식 (파서가 읽음 — 제목 패턴 정확히)
```
# <KEY> <제목>        ← 최상위 블록. KEY 는 지정된 영문 대문자 토큰. 보고서의 '절(H2)' 하나가 됨
### <소제목>          ← 블록 안 소제목(H3). '## ' 은 쓰지 말 것
```
본문 요소: 문단, `- ` 불릿(2칸 들여쓰기=하위), `1. ` 번호, 마크다운 표(헤더+구분줄 필수, 셀 안 줄바꿈·`|` 금지),
```코드 펜스```(40줄 이하), **굵게**, `코드`. 이 외 서식(HTML, 이미지, ####, 인용 >, 링크 [](...)) 금지. URL 은 평문. 표 열은 7개 이하.

파일 마지막에 반드시 (KEY 고정):
```
# PAPERS 참고문헌
- arXiv:ID | 정확한 제목 | 연도 | 한 줄 요지
- STD | 표준/백서/블로그/공식문서 정식 제목 | 발행 주체 | 연도 | URL

# REPOS 저장소
- owner/repo
```
